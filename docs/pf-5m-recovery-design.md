# 通路への再配置を活かした過去軌跡修正の検討案

2026-10-22のユーザー方針を反映。同日、別出力の事後候補を作る初版を実装した。初版は5 m再配置を維持して評価した。その後、ユーザー指示で再配置半径を3 mへ変更した。死亡枠だけの補充は維持する。以下の検討案すべてを実装済みという意味ではない。

再配置半径3 mと、以下の事後候補探索半径5 mは別設定である。後者は今回変更していない。

## 試作した範囲

`uv run rikka particle --history-candidate --pf-seed 0 --no-plot`で実行する。
元の結果を保持し、各時点の元位置とその5 m以内に実在する生存粒子の位置から、
地図を横切らない接続を選び直す。粒子候補は空間の広がりを保って最大24点へ
間引き、元位置も候補に含める。変位二乗、元位置からの距離、各時点の重みを
使う動的計画法であり、センサーの歩幅・方位に候補を制限する処理ではない。

初版は全保存区間を対象とするオフライン候補で、始点・終点は元の仮境界を保持する。
粒子位置間の接続を再選択するもので、歩幅倍率や方位ずれを新しく推定し直す処理、
直近窓だけの修正、前向き状態への反映は未実装。参照した粒子の状態と系譜の切替は
CSVへ記録する。滑らかさと同時に経路を短縮する傾向があるので、精度の検証が必要。

BLE補正を適用した実行は、途中のアンカーを動かさないため候補修正を省略する。
今回の実測と限界は[試作評価](pf-history-prototype-20261022/README.md)に記載した。

## 確認済みの方針

- **センサーに沿った再提案は却下する。** 壁衝突後の候補をセンサーの歩幅・方位の近傍に限定する案は採用しない。
- **現行の半径3 mの再配置を活かす。** 通路上へ粒子を戻せる利点を維持する。探索を通常歩行で説明できる場合だけに制限したり、異常が連続した場合だけに変更したりしない。
- **ESSが粒子数の50%未満なら全粒子を再標本化する。** ユーザーの追加指示で再び有効化した。ESSが十分なときは従来どおり死亡枠だけを補充し、生存枠を保持する。
- **過去軌跡の修正を別機能として検討する。** 現在の再配置を制約する条件として追加せず、再配置した結果を踏まえて過去を再評価する。

ここでいう再配置は、実装上はリサンプリング前の再配置である。死亡枠の補充と区別して記録する。

## 推奨する検討の順序

### 1. 現在の前向き推定を維持し、再配置の履歴を記録する

歩ごとに、通常の移動案、壁衝突の有無、再配置前後の位置、再配置量、親粒子、重みを対応付けて残す。現在の3 m再配置による候補の生成・採用は変えない。

補充先は親の履歴を引き継ぎ、死亡した位置から補充先までを実際の歩行として接続しない。再配置と複製は異なるイベントとして保存する。

### 2. 再配置後の位置を手掛かりに、直近の経路を後ろから再評価する

再配置した地点に至るまでの経路を、直近の粒子履歴・地図・歩行時刻から複数作る。再配置で移動した数mが、以前から蓄積していた位置ずれとして説明できるかを検討する。

例えば、歩幅の過小推定が数歩続いて曲がり角へ届いていなかった可能性や、方位のずれで通路の片側へ寄っていた可能性を、区間全体として調べる。位置の線だけでなく、仮説となる歩幅倍率や方位ずれの推移も対応付ける。

センサーは参考情報として使うが、その近傍に候補を閉じ込める再提案は導入しない。誤差を数歩に均等配分するだけの方法や、センサー推定への強い引き戻しは避ける。地図上の経路、既存の粒子による支持、時間的な整合性を併せて比較する。

### 3. 再配置先にも不確かさがあるものとして扱う

3 m円内で歩行可能だった位置は正解位置とは限らない。単一の再配置先を確定したランドマークのように固定せず、再配置後の粒子群・重み・分岐を含めて過去経路を評価する。

候補が複数の通路へ分かれる場合や、過去との対応を絞れない場合は未確定として保持する。後続の歩行や利用可能な独立の位置情報で区別できるかを見る。

### 4. まず別出力で修正結果を比較する

初期の試作は、現在のPFをそのまま実行した結果に対する事後処理とする。元の軌跡、修正候補、修正区間、理由、修正量を別々に保存する。前向きの粒子状態や再配置の採用判断へは、この段階では反映しない。

これにより「通路へ戻れる利点」と「過去軌跡の修正の効果」を分けて評価できる。表示が滑らかになったことだけで精度改善とは判断しない。

効果を確認できた場合に、直近数歩を仮軌跡として更新するオンライン処理を次の段階で検討する。対象区間の長さや過去状態まで更新する範囲は、まだ確定しない。

## できることと限界

過去軌跡を再評価することで、再配置による位置の変化を複数歩の経路として説明できる可能性がある。一方、別の通路へ誤って復帰した場合などは、誤った再配置先へ過去を合わせる危険もある。

したがって、地図上を通ることに加え、粒子履歴による支持と実ルートとの一致を検証する。説明できない場合は未確定区間・補正イベントとして残す。必ず連続した軌跡が復元できるとは扱わない。

ライブの現在位置は3 m再配置で変化し得る。過去軌跡の修正によって確定後の経路を改善することと、その瞬間の現在位置の変化をなくすことは区別する。

## 実装候補

|場所|検討する役割|
|---|---|
|`particle/lib/propose.py`・`relocate.py`|既存の再配置を維持し、必要なイベント情報を収集|
|`particle/lib/record.py`・共有結果型|再配置、死亡枠補充、元の軌跡と修正候補の対応を記録|
|粒子履歴・経路選択を使う新たな処理|保存済み履歴から過去経路を再評価。恒常機能にする場合は`src/rikka/`へ実装|
|`particle/lib/recovery/checkpoint.py`|既存の歩列再生が候補経路の生成に利用できるか調査|
|`plot/`|元の推定、過去修正、未確定区間、補正イベントを区別して表示|

既存のcheckpoint再生をそのまま採用するとは決めない。センサー近傍への限定を持ち込まないこと、前向き推定へ及ぼす影響、履歴との整合性を確認する。

## 評価

同じ前向きPFの結果について、過去修正なし／ありを比較する。現行3 m再配置・死亡枠だけの補充を共通条件とし、直近19-17-08、18-52-40、既存の同一路線計測を候補とする。

修正区間・修正量・壁交差・分岐・未確定率・処理時間と、地図に整合した正解ルートに対する誤差を確認する。通路への復帰率と、正しい通路へ復帰した割合は区別する。ESSは別の診断として残す。

センサーに沿った再提案、再配置をセンサー近傍へ限定する変更は、この案に含めない。ESS低下時の全粒子再標本化は、過去修正とは独立した前向きPFの設定としてユーザー指示で再適用した。
