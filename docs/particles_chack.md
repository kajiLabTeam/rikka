- 現状
	- パーティクルにかかる歩幅の誤差の数値が大体1.2倍程度
		- 70cmの歩幅が85cmになる程度
	- パーティクルにかかる方向の誤差が2度程度
	- 歩行不可能領域に落ちたパーティクルのリサンプリング範囲が30cm程度
	- パーティクルは個々がPDRに沿って動いてその範囲がサンプリングされた方向，位置に沿って動いている
	- 推定される位置は歩行可能領域にあるパーティクル全てを加重平均かけてその中央にあるものを選択している

## 回答（既定設定での実測検証）

- 検証条件
	- 入力: `input/sensor_data/hiroto/hiroto_1turn_rightsidestep_3turn_leftsidestep`（95歩、決定論歩幅 平均 0.796 m）
	- 地図: `input/Floormap_building14_5floor.png`、起点 `(2972,245)`px、縮尺 0.01 m/px、初期方位 90度（EXP-060 で承認済みの条件）
	- PF: 500粒子、BLEなし、adaptive-causal、seed `[0,1,2]`
	- 既定の `FLOORMAP_ORIGIN_PX = (2050,400)` は画素値0（壁）で `_validate_floormap_origin` が ValueError になるため、承認済み起点を使用した

### 1. 歩幅の誤差が1.2倍程度（70cm→85cm） → 誤り

- 歩幅倍率 `stride_scale` のハードクリップは `PF_STRIDE_SCALE_MIN/MAX = 0.90 / 1.15` で、**1.2倍は構造上とれない**
- 実測の重み付き平均倍率は **0.90〜1.03**（歩ごとの中央値 0.95〜0.98）。粒子間ばらつきは 1σ で ±0.030〜0.037
- 事前中心が `PF_STRIDE_SCALE_PRIOR_MEAN = 1.03` なのに実測が 0.95〜0.98 に偏る。壁衝突で歩幅の大きい粒子が落ち、短い粒子が生き残るため**縮む側へ張り付いている**
- 70cm の歩幅は 85cm ではなく **66〜72cm 程度**。拡張範囲 `[0.60, 1.50]` に切り替わる `adaptive_stride_state` も、この計測では条件（相対不確かさ ≥ 0.18）を満たす歩が 0/95 で発火していない
- 1歩ごとの乗算ノイズは別途 `PF_SIGMA_STEP_LENGTH_RATIO = 0.01`（±1%、1σ）。実効歩幅の粒子間ばらつきは 1σ で約 3.7〜4.3%（±3cm）

### 2. 方向の誤差が2度程度 → おおむね正しい

- 実測の方位ばらつきは中央値 **1.3〜1.7度**、p90 で約 4度。概ね「2度程度」で合っている
- ただし横歩き・旋回の歩では最大 **14.6〜32.7度**まで跳ねる（別起点の条件では 126度を観測）。常時2度ではない
- 内訳: 初期 `PF_SIGMA_INIT_HEADING = 0.03` rad(1.72度)、1歩ごと `PF_SIGMA_HEADING = 0.01` rad(0.57度) を保持率 0.85 の AR(1) で積む（定常 1σ ≈ 1.1度）。実測が理論値より大きいのは `σ = max(0.01, 0.15 × 事後方位標準偏差)` で適応PDRの不確かさが乗るため
- なお `heading_correction` は0で初期化されたまま更新されず、角度のゆらぎは実質 `heading_drift` のみ

### 3. 歩行不可能領域に落ちた粒子のリサンプリング範囲が30cm程度 → 数値はおおむね正しいが、仕組みの理解が不正確

- 数値: 粒子雲の位置RMS広がりは中央値 **0.22〜0.44 m**、p90 約 0.6 m。「30cm程度」はこの範囲に収まる
- 仕組み: **リサンプリングは新しい位置を生成しない**。`ctx.particles = ctx.proposed_particles[ctx.indices]` で、歩行可能な生存粒子の位置を重みに応じて**復元抽出（重複コピー）**するだけ。位置へのノイズ付加は一切なく、ジッタが乗るのは方位ドリフト(+0.009 rad)と歩幅倍率(+0.003)のみ
- したがって再配置先は「落ちた粒子の周囲30cm」ではなく、**その時点で生き残っている粒子雲の内側**。雲は進行方向1σ 0.23 m／横方向1σ 0.07 m の細長い形（長軸:短軸 ≈ 3:1）で、1歩で付け加わる広がりは前後・横ともわずか約3cm
- 発動条件は `ESS < PF_RESAMPLE_ESS_RATIO × N = 0.5 × 500 = 250`
- 粒子がほぼ全滅した場合（有効重み粒子が `PF_RECOVERY_VALID_RATIO = 0.05` 未満）だけ recovery の候補グリッドに切り替わり、ここは範囲が広い
	- `local_grid`: 前歩位置から半径 0.69〜0.85 m（倍率 0.9/1.0/1.1）、角度 ±5/10/20/30/45度 の扇形 → 横 ±0.54 m、弦長 約1.1 m
	- `turn_grid`（旋回・横歩き歩のみ）: ±60/90/135/180度 → 前歩位置を中心にほぼ全周のリング
	- `checkpoint_replay`: 過去の健全チェックポイントまで巻き戻して再生 → 位置が数m単位で移動

### 4. 粒子は個々がPDRに沿って動き、その範囲がサンプリングされた方向・位置に沿って動く → 正しい

- 各粒子は共有の決定論PDRステップ（方位・歩幅）に自分のノイズを足して進む: `θᵢ = 状態別基準方位 + heading_driftᵢ`、`Lᵢ = 決定論歩幅 × stride_scaleᵢ × (1 + N(0,0.01))`
- 補足: `calibration_reliability ≥ 0.85` または横歩きクラスタ外の歩では、運動4状態（前進／左右横歩き／旋回）の基準方位が**全て同一値に畳まれる**。そのため大半の歩で粒子間の方位差はドリフトノイズだけになり、方位の多様性はほぼ生まれない
- 条件を外れた歩だけ 前進=体方位 / 横歩き=体方位±90度 / 旋回=移動方位 の4択になる。連続ノイズ(±1〜2度)と離散候補(±90度)の間、つまり中間角度を提案する経路が存在しない

### 5. 推定位置は歩行可能領域の全粒子を加重平均し、その中央にあるものを選択 → 部分的に誤り

- 既定は `PF_PATH_SELECTION = "sequence"`。**まず単一祖先経路(sequence)と加重平均経路(current)の両方を作り、センサー根拠のない進行方向反転が少ない方を選ぶ**。sequence が選ばれた場合は加重平均ではなく、累積事後スコア最大の**単一粒子の系譜**がそのまま代表軌跡になる
	- 今回の条件では3seed全てで `current` が選択されたが、別の起点では seed 0/2 が `sequence` を選んだ。seed・起点で選択方式が入れ替わる
- `current` 側も「歩行可能領域の全粒子」ではない。`_dominant_reachable_cluster` で**互いに壁を越えずに直線到達できる粒子クラスタ**に分け、合計重みが最大のクラスタ**内の粒子だけ**を加重平均する。壁の向こう側の粒子は平均に混ぜない
- さらに動的計画法で経路を組むため、加重平均点が歩行不可／前時点から到達不可になる時点では `particle_fallback` に切り替わり、**平均点ではなく実在する単一粒子の座標**を使う（今回 95歩中 0〜1歩で発生）
- 「その中央にあるものを選択」という表現は不正確。選ばれるのは加重平均の**座標そのもの**（`weighted_mean`）で、平均に最も近い粒子を選ぶ処理ではない


## 2026-10-21追記: 動画で壁上の粒子が生き残って見える理由

この節はEXP-062の変更後の挙動を対象とし、上記の狭い提案分布を使った過去の測定とは区別する。

動画の水色の点は「重みが正の粒子」ではなく、固定長配列に残っている全粒子を表す。このため、動画だけで粒子の生死を判断できない。

1. 壁に入る移動案は、直ちに重み0にせず、前歩位置を中心とする半径5 m以内で最大20回再配置する。前歩位置から再配置先までの線分が全て歩行可能な場合だけ救済する。
2. 再配置に失敗した粒子は地図尤度0となり、重みも0になる。推定上は死亡しているが、ESSが粒子数の半分を下回らず再標本化を省略した歩では、座標は配列に残る。重み0の粒子にも次歩の位置提案処理が走るので、映像では動き続けるように見える。
3. `record.py`は重み0も含む全座標を保存し、`plot/lib/animation.py`は重みを受け取らず全座標を同じ水色・同じ大きさで描く。これが生存粒子と死亡粒子を区別できない直接の原因。加えて、点の中心が通路上でも、描画マーカーの円周が壁へ重なる場合がある。

## 2026-10-21追記: 重み0の粒子を即時に再標本化する変更

上の「壁上粒子が残る」測定は変更前の履歴。ユーザーの指示により、現在は次の条件に変更した。

- 以前: `ESS < 0.5N` の場合だけ全粒子を再標本化する。例えば500粒子中1個が重み0でも、残る499個が均等ならESSは499で、再標本化されない。
- 現在: **重み0の粒子が1個でもある場合、または `ESS < 0.5N` の場合に全粒子を再標本化する**。生存粒子だけから重みに応じて500個を復元抽出し、重みを1/500に戻す。これは死亡した枠だけを補充する方式ではなく、既存の系統再標本化を即時に実行する方式。
- 累積重みの境界と乱数が一致する場合も重み0の親を選ばないよう、累積和の探索を `side="right"` にした。
- 全滅時は従来どおり復旧処理を使用する。また、地図判定後の5 m再配置はそのままで、救済できた粒子は重み0にならない。今回の変更は再配置に失敗するなどして実際に重み0となった粒子を対象にする。

## 2026-10-21追記: 死亡した枠だけを補充する方式へ変更（現在の通常更新）

EXP-064の全粒子再標本化は、ユーザーの追加指示により死亡枠のみの補充へ変更した。

- 重み0の枠だけ、生存粒子の重みに応じて親を抽出して置き換える。500個中3個が死亡したら、497個の生存枠は保持し、3枠だけを補充する。
- リサンプリング時に生存粒子の位置・方位・歩幅倍率・運動状態は変更せず、親インデックスも自分自身のままにする。通常の次歩予測では従来どおりプロセスノイズが加わる。
- 親の重みを元の生存枠と補充先で等分する。例えば重み0.12の親から2枠を補充したら、元の親と2複製の各重みは0.04になる。系統の合計重み0.12を保ち、粒子全体の重み合計は1になる。
- 再標本化後の方位・歩幅ノイズは補充先だけに加える。ESSが低いだけでは通常更新で全粒子を再標本化しない。`PF_RESAMPLE_ESS_RATIO`はAPI互換性のため残しているが、通常の補充判定には使わない。
- 全滅時の復旧、確定ランドマークの位置・方位補正は別処理。既存の5 m再配置も維持しているため、そこで救済された粒子は死亡枠として扱わない。
